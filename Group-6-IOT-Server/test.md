## 🚀 1. การเตรียมความพร้อมก่อนเริ่มนำเสนอ

ก่อนอาจารย์เรียกตรวจงาน ให้เปิดโปรแกรมเตรียมไว้ 2 หน้าต่าง:

### หน้าต่างที่ 1: รันเซิร์ฟเวอร์
เปิด Terminal (PowerShell) ในโฟลเดอร์โปรเจกต์:
```powershell
cd "C:\Users\Asus\OneDrive\เดสก์ท็อป\IOT-Door\iot-door-lock-server\Group-6-IOT-Server"
npm start
```
*(จะเห็นข้อความยืนยันว่าเซิร์ฟเวอร์เปิดทำงานที่ Port 3000)*

### หน้าต่างที่ 2 (เทคนิคเรียกคะแนน!): เปิดดู Log สดแบบ Real-time
เปิด PowerShell อีกหน้าต่างหนึ่ง แล้วพิมพ์คำสั่งนี้ค้างไว้:
```powershell
cd "C:\Users\Asus\OneDrive\เดสก์ท็อป\IOT-Door\iot-door-lock-server\Group-6-IOT-Server"
Get-Content .\logs\log.txt -Tail 5 -Wait
```
*(หน้าต่างนี้จะรอตรวจจับ เมื่อเรากดปุ่มบนหน้าเว็บ Log บรรทัดใหม่จะเด้งขึ้นมาในจอนี้ทันทีแบบสดๆ)*

## 🎬 2. สคริปต์ขั้นตอนการสาธิตสดให้อาจารย์ดู

### 🟢 ฉากที่ 1: การสแกน QR Code และเข้าห้อง (Auto Check-In V2)
1. **เปิดเบราว์เซอร์ไปที่:**  
   👉 `http://localhost:3000/?room=LAB-401`
2. **ชี้ให้อาจารย์ดูจุดเด่น:**
   * **โลโก้สถาบัน KMITL** ด้านบน เพื่อความเป็นทางการของระบบ
   * **รหัสห้อง LAB-401** ที่ระบบดึงมาจาก URL Parameter ของ QR Code อัตโนมัติ
   * **ปุ่มกดรูปตา `👁️` / `🙈`** ข้างช่องรหัสผ่าน สำหรับกดดู/ซ่อนรหัสผ่าน เพื่อเช็คว่าพิมพ์ถูกต้องไหม
3. **กรอกข้อมูลบัญชีทดสอบ:**
   * **รหัสนักศึกษา:** `67200412`
   * **รหัสผ่าน:** `rujinat_fah` *(ลองกดปุ่มรูปตาให้อาจารย์ดูว่ารหัสผ่านแสดงขึ้นมาจริง)*
4. **กดปุ่ม "เข้าสู่ระบบ (Sign In)":**
   * **อธิบายอาจารย์:** *"ระบบ Version 2 ของกลุ่มเรา ล็อกอินถูก = ถือว่าเข้าห้องทันที (Auto Check-In) กลอนประตูปลดล็อค 5 วินาที โดยไม่ต้องกดปุ่มยืนยันซ้ำซ้อน"*
   * **ชี้ให้ดูหน้าจอ Dashboard:**
     * ข้อความต้อนรับ: **"ขอต้อนรับเข้าสู่ห้อง LAB-401"**
     * ชื่อผู้ใช้: **Rujinat Fah (รหัส: 67200412)**
     * เวลาที่เข้าห้องจริง
     * **นาฬิกา Real-time Stopwatch:** นับเวลาที่อยู่ในห้อง (HH:MM:SS) เดินหน้าแบบเรียลไทม์
     * **มีปุ่มออกจากห้องเพียงปุ่มเดียว**

### 🔥 ฉากที่ 2: ไฮไลต์เด็ด! การสลับห้องอัตโนมัติ (Smart Timestamp Comparison)
*(จุดนี้มักเป็นคำถามที่อาจารย์ชอบถาม: "ถ้านักศึกษาลืมกดออกจากห้องเดิม แล้วเดินไปเข้าห้องอื่น ระบบจะพังไหม?")*

1. **การสาธิต:**
   * ในขณะที่หน้าจอแรกยังอยู่ในห้อง `LAB-401`
   * ให้เปิด **แท็บใหม่ในเบราว์เซอร์** ไปที่ห้องอื่น:  
     👉 `http://localhost:3000/?room=LAB-402`
   * ล็อกอินด้วยรหัสเดิม: `67200412` และ `rujinat_fah`
2. **อธิบายอาจารย์:**
   * *"ระบบ State ของกลุ่มเราจะตรวจพบว่า คุณรุจินาถ มีประวัติอยู่ในห้อง LAB-401 แต่กำลังสแกนเข้า LAB-402"*
   * *"ระบบจะนำเวลาปัจจุบันไป **ตัดสถานะออกจากห้อง LAB-401 ให้เป็น OUT อัตโนมัติ** พร้อมบันทึกลง Log ทันที"*
   * *"จากนั้นทำการ **Check-In เข้าห้องใหม่ LAB-402 เป็น IN ให้ทันที** ประตูห้องใหม่ปลดล็อค และหน้าจอนับเวลาเริ่มต้นใหม่แบบไร้รอยต่อ"*
3. **เปิดสลับกลับมาดูที่แท็บห้องเก่า (LAB-401):**
   * **ชี้ให้อาจารย์ดูความฉลาดของระบบ Real-time Session Sync:**
     * หน้าจอห้องเดิม (LAB-401) จะตรวจพบอัตโนมัติภายใน 2.5 วินาทีว่าผู้ใช้ย้ายไปห้องใหม่แล้ว!
     * นาฬิกาจับเวลาจะหยุดเดินทันที และ **เด้งแจ้งเตือนพร้อมสลับกลับไปหน้า Login ของห้อง LAB-401 อัตโนมัติ**
     * หากผู้ใช้พยายามกดปุ่มออกจากห้อง LAB-401 บนหน้าจอเก่า ระบบจะป้องกัน (Room Mismatch Protection) และไม่ไปลบ Session ของห้องใหม่เด็ดขาด!
4. **เปิดหน้าต่าง PowerShell หรือไฟล์ Log ให้อาจารย์ดู:**
   * จะเห็นบรรทัด `LAB-401 | OUT` และตามด้วย `LAB-402 | IN` ทันที (สถานะในระบบมีเพียง IN และ OUT เท่านั้น)!

### 🔴 ฉากที่ 3: การกดออกจากห้องตามปกติ (Check-Out)
1. ในหน้าห้อง `LAB-402` ให้กดปุ่มสีแดง **"🚪 ออกจากห้อง (Check-Out)"**
2. จะมีกล่องข้อความยืนยัน ➔ กดยืนยัน
3. **อธิบายอาจารย์:**
   * ประตูห้อง LAB-402 ปลดล็อคเพื่อให้ผู้ใช้เดินออกจากห้อง
   * ระบบบันทึก Log สถานะ `[OUT]` ลงไฟล์
   * หน้าจอกลับสู่หน้า Login ปกติ พร้อมให้ผู้ใช้คนถัดไปใช้งาน

---

### 🛡️ ฉากที่ 4: การทดสอบความปลอดภัย (Security Rejection)
1. ลองกรอกรหัสนักศึกษาอื่น เช่น `64099999` หรือใส่รหัสผ่านผิด
2. กดเข้าสู่ระบบ ➔ ระบบจะปฏิเสธทันที และแจ้งเตือนสีแดงว่าไม่พบข้อมูลในฐานข้อมูล RADIUS

## 📁 3. ตำแหน่งไฟล์ Log และวิธีดูข้อมูลที่ส่งให้กลุ่มอื่น

ข้อมูลประวัติการเข้า-ออกของกลุ่มที่ 6 ถูกเก็บและส่งต่อให้กลุ่มอื่น **2 ช่องทางหลัก** ดังนี้:

### 📍 ช่องทางที่ 1: ไฟล์จริงบนเครื่องคอมพิวเตอร์ (Physical File)
* **ตำแหน่งโฟลเดอร์:**
  ```text
  C:\Users\Asus\OneDrive\เดสก์ท็อป\IOT-Door\iot-door-lock-server\Group-6-IOT-Server\logs\
  ```
* **ชื่อไฟล์:**
  ```text
  log.txt
  ```
* **วิธีเปิดดู:**
  * **วิธีเปิดธรรมดา:** ดับเบิลคลิกเปิดไฟล์ `log.txt` ด้วยโปรแกรม **Notepad** หรือเปิดใน **VS Code**
  * **วิธีเปิดดูสด (Real-time Stream):** รันคำสั่งใน PowerShell:
    ```powershell
    Get-Content "C:\Users\Asus\OneDrive\เดสก์ท็อป\IOT-Door\iot-door-lock-server\Group-6-IOT-Server\logs\log.txt" -Tail 10 -Wait
    ```
* **รูปแบบข้อมูล 5 คอลัมน์ภายในไฟล์:**
  ```text
  [2026-10-07 08:30:15] | 64010123 | Somchai Jaidee       | LAB-401  | IN
  [2026-10-07 09:45:00] | 64010123 | Somchai Jaidee       | LAB-401  | OUT
  [2026-10-06 17:33:20] | 67200412 | Rujinat Fah          | LAB-401  | IN
  [2026-10-06 17:33:20] | 67200412 | Rujinat Fah          | LAB-401  | OUT
  [2026-10-06 17:33:20] | 67200412 | Rujinat Fah          | LAB-402  | IN
  ```

---

### 🌐 ช่องทางที่ 2: REST API Endpoint สำหรับส่งให้กลุ่ม 4 (Web Application)
* **URL สำหรับดึงข้อมูล:**
  ```text
  http://localhost:3000/api/logs
  ```
  *(เมื่อรันบน Proxmox วงแลน `vmbr1` จะเป็น `http://10.10.10.16:3000/api/logs`)*
* **วิธีเปิดดู:**
  * สามารถเปิดผ่าน Google Chrome หรือ Edge ได้ทันที พิมพ์ URL ด้านบน จะแสดงข้อความประวัติทั้งหมด
* **การนำไปใช้งานของกลุ่ม 4:**
  * ทีมกลุ่ม 4 (ผู้ทำ Web Portal รวม) จะเขียนโค้ดยิง HTTP GET มาที่ Endpoint นี้ เพื่อดูดเนื้อหาข้อความไปแปลง (Parse) แยกตามห้องและเวลา เพื่อพล็อตเป็น **กราฟแท่งสถิติการใช้งานห้องเรียน** บนหน้าเว็บของมหาวิทยาลัย

## 💡 4. แนวทางการตอบคำถามอาจารย์ (Q&A Defense Tips)

* **ถาม: ทำไมกลุ่ม 6 ไม่ใช้ Docker?**
  * **ตอบ:** *"กลุ่มเราเลือกใช้ Pure Native Node.js เพื่อหลีกเลี่ยง Overhead ของ Container และรับประกันความเข้ากันได้ 100% บนทุกสภาพแวดล้อม ทั้งเครื่องพัฒนา Windows และ VM บน Proxmox โดยไม่มีปัญหา Kernel Crash หรือจอฟ้าครับ"*
* **ถาม: การเชื่อมต่อกับ RADIUS และ Database ทำอย่างไร?**
  * **ตอบ:** *"ในเฟสพัฒนานี้ กลุ่มเราจำลองฐานข้อมูลไว้ที่ `backend/mock-data/users.json` สำหรับผู้ใช้ 67200412 และเขียนโครงสร้างใน `authService.js` ให้พร้อมสลับไปใช้ `PRODUCTION_API` ชี้ไปที่ VM 103 (กลุ่ม 3) ทันทีที่เชื่อมต่อสายแลนเสมือน `vmbr1` ครับ"*
* **ถาม: ปัจจุบันสั่งฮาร์ดแวร์จริงหรือยัง?**
  * **ตอบ:** *"กลุ่มเราตัดการเชื่อมต่อ MQTT จริงออกชั่วคราวเพื่อประหยัดทรัพยากร แต่ได้สร้าง Door Simulator รองรับคำสั่งปลดล็อค 5 วินาที พร้อมส่งผ่าน MQTT Topic `iot/door/{room}/command` ทันทีเมื่อบอร์ด ESP32 ของกลุ่ม 7 เชื่อมต่อเข้ามาครับ"*
