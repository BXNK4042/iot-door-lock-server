# 📝 Logs Documentation (ระบบบันทึกประวัติ)
## โฟลเดอร์ `logs/` มีไว้ทำไม และโครงสร้างเป็นอย่างไร?

### 1. วัตถุประสงค์
โฟลเดอร์นี้มีหน้าที่จัดเก็บประวัติการเข้า-ออกห้องของนักศึกษาทุกคน เพื่อเป็นหลักฐานการใช้งาน (Audit Trail) และเป็น **แหล่งข้อมูลดิบที่ต้องส่งมอบให้กับทีม Web Application (กลุ่ม 4)** นำไปประมวลผลแสดงกราฟสถิติบน Dashboard รวมของมหาวิทยาลัย

---

### 2. โครงสร้างไฟล์ `log.txt` (5 คอลัมน์มาตรฐาน)
บันทึกข้อมูลแบบ **Append-only** (เขียนต่อท้ายเสมอ ไม่เขียนทับ) โดยแต่ละบรรทัดคั่นด้วยสัญลักษณ์ ` | ` ดังนี้:

| คอลัมน์ที่ | ชื่อฟิลด์ | คำอธิบาย | ตัวอย่างข้อมูล |
|---|---|---|---|
| **1** | **Timestamp** | วันที่และเวลาที่ทำรายการ (YYYY-MM-DD HH:mm:ss) | `2026-10-07 08:30:15` |
| **2** | **Student ID** | รหัสนักศึกษา 8 หลัก | `64010123` |
| **3** | **Student Name** | ชื่อ-นามสกุล ที่ได้จาก Authentication API | `Somchai Jaidee` |
| **4** | **Room ID** | รหัสห้องที่ขอเข้าใช้งาน | `LAB-401` |
| **5** | **Action Status** | สถานะการกระทำ (มีเพียง IN หรือ OUT เท่านั้น) | `IN` |

---

### 3. ตัวอย่างเนื้อหาจริงภายในไฟล์ `log.txt`
```text
[2026-10-07 08:30:15] | 64010123 | Somchai Jaidee       | LAB-401  | IN
[2026-10-07 09:45:00] | 64010123 | Somchai Jaidee       | LAB-401  | OUT
[2026-10-07 10:15:20] | 64010888 | Suda Rakrian         | LAB-402  | IN
[2026-10-07 11:30:00] | 64010888 | Suda Rakrian         | LAB-402  | OUT
[2026-10-07 11:30:00] | 64010888 | Suda Rakrian         | LAB-401  | IN
```

### 4. การส่งมอบข้อมูลให้ทีมกลุ่ม 4 (Web Application)
กลุ่ม 6 จัดเตรียม 2 ช่องทางในการส่งต่อข้อมูลให้กลุ่ม 4:
1. **ผ่าน REST API Endpoint:** กลุ่ม 4 สามารถยิง HTTP GET มาที่ `http://10.10.10.16:3000/api/logs` เพื่อดึงข้อมูลข้อความทั้งหมดไป Parse เป็น JSON
2. **การแชร์ไฟล์โดยตรง:** ส่งไฟล์ `log.txt` นี้ให้กลุ่ม 4 นำไปประมวลผลสถิติ
